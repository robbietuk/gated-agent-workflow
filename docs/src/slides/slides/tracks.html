Three tracks for features, bugs and small changes

Feature

Full workflow

/wf-start · /wf-research · /wf-brainstorm · /wf-plan · /wf-build · /wf-pr

Spec, research, brainstorm, planning, slices, PR.

Example: a new configuration parameter for an instrument.

Bug

Root cause first

/wf-start · /wf-debug · /wf-build · /wf-pr

Reproduce, lock a failing regression test, find the root cause with evidence. You approve the cause and fix, then one slice and a PR.

Example: a sync message dropped after reconnect.

Small change

One slice

/wf-start · /wf-plan · /wf-build · /wf-pr

Spec, a one-slice outline you approve, build, PR.

Example: a wrong label or log message.

/wf-start picks the track. A bug whose root cause is a design flaw moves to the brainstorm loop.

Most of our work is features and bugs, so the bug track gets its own path. It follows systematic debugging: no fix without a root cause, and the regression test must fail before the fix.
