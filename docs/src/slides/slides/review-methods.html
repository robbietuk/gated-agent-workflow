Six methods for the branch code review

Whole branch vs design

Catches drift between slices, duplicated logic and anything that misfits the design.

Parallel narrow lenses

One fresh reviewer each: safety, concurrency, error handling, compatibility, traceability.

Verify pass

A second agent must show the failing inputs and state. Unconfirmed findings are dropped.

Severity ranking

Blockers escalate. Important issues get fixed. Nits are fixed automatically.

A second model

A different model from the one that wrote the code catches different mistakes.

Test adequacy

Every req ID has a test that fails if its code is removed.

Narrow checklists beat one general reviewer. The verify pass is what keeps the noise down: a finding only survives if it can name a concrete failure.
